# Sisyphus scheduler — measured results (V3)

Generated by `python -m sisyphus.results`. Every byte count comes from the real
`ResidencyCache` + `ExpertMajorScheduler` running real `Call` objects; throughput and
tokens/night are derived from those bytes with the stated machine envelope. Nothing here
is hand-edited.

## Envelope (geometry.py)

| quantity | value | status |
|---|---|---|
| model on disk (trunk + experts, Q2) | 841 GB | measured off the download |
| trunk pinned in RAM | 60 GB | measured |
| expert | 9.7 MB | measured |
| hot set at hot_frac 0.10 / 0.15 | 78 / 117 GB | depends on the bracketed skew |
| KV per context token (MLA latent, fp16) | 0.67 MB | estimate from latent dim |
| OS reserve | 6 GB | assumption |
| decode compute | 0.12 core-s/token | BRACKETED |
| job shape | 512 prompt + 256 decode tokens | assumption |

**Expert cache = RAM − trunk − OS − KV.** The V2 tables gave a 128 GB machine a 100 GB
expert cache; with the trunk resident that machine has about 46 GB. The tables below use
the derived budget. `128GB + trunk on 64GB GPU` shows what the old number implicitly
assumed.

## Notes

NOTE: bytes come from the real ResidencyCache/scheduler, not a formula. tok/s = batch / max(I/O, compute) per step with I/O overlapped behind compute (Spotlight); compute 0.12 core-s/token (BRACKETED). tokens/night charges one prefill per convoy. 'skip' is the mean fraction of a token-layer's gate mass dropped by residency-aware routing — the quality proxy the profiling harness calibrates. Routing skew, cold gate weight and compute are the bracketed unknowns sisyphus.profiling replaces with measured numbers.
