# Sisyphus scheduler — measured results (V4)

Generated by `python -m sisyphus.results`. Every byte count comes from the real
`ResidencyCache` + `ExpertMajorScheduler` running real `Call` objects; throughput and
tokens/night are derived from those bytes with the stated machine envelope. Nothing here
is hand-edited.

## Envelope (geometry.py)

| quantity | value | status |
|---|---|---|
| model on disk (trunk + experts, Q2) | 841 GB | measured off the download |
| trunk pinned in RAM | 62 GB | measured |
| expert | 9.68 MB | measured |
| hot set at hot_frac 0.10 / 0.15 | 77 / 117 GB | depends on the bracketed skew |
| KV per context token (MLA latent, fp16) | 0.03 MB | estimate from latent dim |
| OS reserve | 6 GB | assumption |
| work per token | 208 GFLOP (92 experts / 116 trunk) | from parameter count |
| CPU effective / DRAM | 1.0 TFLOPS / 80 GB/s | BRACKETED — Phase 0 measures |
| GPU effective / PCIe x16 | 100 TFLOPS / 50 GB/s | BRACKETED |
| job shape | 512 prompt + 256 decode tokens | assumption |

**Expert cache = RAM − trunk − OS − KV.** The V2 tables gave a 128 GB machine a 100 GB
expert cache; with the trunk resident that machine has about 46 GB. The tables below use
the derived budget. With a GPU holding the trunk the RAM budget recovers those 60 GB.

**Compute is a model, not a constant (V4).** Each step's wall is the slowest of SSD,
memory/PCIe traversal and FLOPs. `cpu` = experts and trunk on the cores; `gpu-trunk` =
attention/shared/dense in VRAM; `gpu-x16` / `gpu-x8` = experts streamed through the GPU
over PCIe each step, trunk in VRAM. The `bound` column names what is binding.

## Notes

NOTE: bytes come from the real ResidencyCache/scheduler, not a formula. Each step's wall is max(SSD, memory/PCIe traversal, FLOPs) — the Spotlight ideal of perfect overlap (real engines lose 15-25%). 'bound' names the binding resource. Compute is a model (geometry.ComputeModel): ~208 GFLOP/token split 92 experts / 116 trunk; CPU 1 TFLOPS effective, DRAM 80 GB/s, GPU 100 TFLOPS, PCIe x16 50 GB/s — all BRACKETED until Phase 0 measures them. 'pre m' is prefill minutes per convoy. tokens/night charges one prefill per convoy. 'skip' is the mean fraction of a token-layer's gate mass dropped by residency-aware routing — the quality proxy the profiling harness calibrates.
